# 🤖 AI-Driven Software Factory (Multi-Agent Architecture)

Welcome to the **AI-Driven Software Factory**. This repository is not just a standard boilerplate; it is an autonomous, multi-agent development ecosystem designed to plan, architect, develop, secure, test, and document software applications dynamically.

Instead of writing code manually line-by-line, you will act as the **Product Owner / Tech Lead**, interacting with a team of specialized AI personas (Agents) through predefined workflows.

---

## 🏗️ Directory Architecture

The workspace is strictly organized to separate AI logic from the actual application code.

```text
my-project/
├── .agents/                      # 🧠 The "Brain" of the Factory
│   ├── agents.md                 # Defines the AI personas and their models.
│   ├── project_standards.md      # The "Constitution" (Immutable tech stack & security rules).
│   ├── skills/                   # Prompt instructions for each agent's specific job.
│   └── workflows/                # The operational pipelines (e.g., /startcycle, /brainstorm).
├── production_artifacts/         # 📝 Blueprints & Specs
│   ├── Technical_Specification.md# Generated by the PM (User Stories, Rules).
│   └── ui_specs/                 # Generated JSON files defining UI behavior, validations, and design tokens.
├── app_build/                    # 💻 The Actual Application Codebase (Monorepo)
│   ├── frontend/                 # e.g., React.js / Vite
│   └── backend/                  # e.g., Node.js / Express
├── docs/                         # 📚 Living documentation generated by the Architect.
└── README.md                     # You are here.
```

## 👥 Meet the Team (The Agents)
The system relies on a specialized team of AI personas, defined in .agents/agents.md. Each persona executes specific skills:

@pm (Product Manager): Interviews you, defines the MVP scope, and generates the Technical_Specification.md and UI JSON blueprints.

@designer (UI/UX Designer): Reads the PM's JSONs, defines design tokens (colors, typography), and generates visual assets and image prompts.

@architect (Solutions Architect): Defines the system architecture, directory tree, database schema, and acts as your sparring partner during brainstorming.

@engineer (10x Full-Stack Developer): Writes the actual code and unit tests inside app_build/, strictly following the Architect's design and the project_standards.md.

@secdevops (Security Auditor): Reviews the Engineer's code for vulnerabilities (e.g., IDOR, Mass Assignment, SQLi) and enforces security patches.

@qa (Quality Assurance): Validates if the code meets all business rules, tests edge cases, and verifies UI error messaging.

@pentester (Offensive Security): Simulates black-box attacks on the compiled code to ensure absolute resilience.

## 🚀 How to Operate the Factory (Workflows)
You control the factory using trigger commands in your AI IDE chat.

### 1. The Planning Phase: /brainstorm
Before any code is written, you must define the technical landscape.

Command: Type /brainstorm I want to build a [feature]. What are the best architecture options?

Action: @architect will act as your Tech Partner, presenting multiple solutions, pros/cons, and evaluating trade-offs.

Outcome: Once you agree on a technology (e.g., "Let's use PostgreSQL and WebSockets"), the Architect will automatically update the .agents/project_standards.md file.

### 2. The Execution Phase: /startcycle
Once the planning is done and the standards are set, it is time to build.

Command: Type /startcycle

Action: This triggers the main assembly line.

@pm gathers requirements and writes specs.

@designer creates the visual identity.

@architect creates the folder structure.

@engineer writes the code and tests.

@secdevops & @qa run the validation loop (sending code back to the Engineer if bugs are found).

@pentester tries to break the system.

@engineer spins up the local server for you to test visually.

Human-in-the-Loop: The execution will pause at key gates (after the PM and Architect phases) for your manual approval before writing code.

## 📜 The Constitution: project_standards.md
The .agents/project_standards.md file is the most important file in this repository. It contains the immutable technical rules for the project.

It dictates the tech stack (e.g., React, Node, Postgres), security constraints (JWT, UUIDv4, Fail-Closed architecture), and prevention against common vulnerabilities (IDOR, Mass Assignment). Never delete this file. If you want the AI to change its fundamental behavior or tech stack, update this file.

🔌 How to Add a New Agent or Skill
This ecosystem is highly scalable. To add a new persona (e.g., @dba for complex database migrations or @devops for AWS deployments), follow these 3 steps:

Define the Persona: Open .agents/agents.md and add the new role, specifying its AI model (e.g., gemini-1.5-flash), goal, and traits.

Give them a Skill: Create a new Markdown file inside .agents/skills/ (e.g., configure_aws.md). Write explicit, step-by-step instructions on what they must do, read, and output.

Inject into a Workflow: Open the workflow where they belong (e.g., .agents/workflows/startcycle.md) and add a step calling the agent and their skill:

Example: "6. @devops executes skills/configure_aws.md to setup the CI/CD pipeline."

## 💡 Pro-Tip: Reverse-Engineering Legacy Code
You do not need to start from scratch. If you have an existing project with no documentation or tests:

Move your existing code into the app_build/ folder.

Open the chat and type: /startcycle @pm, read the existing code in app_build/ and generate the Technical Specs and UI JSONs based on what is already built. Then let the rest of the team run audits and write the missing tests.

The agents will reverse-engineer your code, document it, fix vulnerabilities, and generate the test suite automatically!

## 🔄 The Evolution Loop (How Changes Cascade)

One of the most powerful features of this framework is its **Spec-Driven propagation**. When you change a technical decision or product rule during a `/brainstorm` session, you never need to manually refactor or track down what needs to be updated. The architecture handles it end-to-end.

The pipeline follows a strict, single source of truth cascade:

```text
 [/brainstorm] ➔ Updates `project_standards.md` / `Technical_Specification.md`
                       │
                       ▼
 [/startcycle] ➔ [1. @pm / @designer] Re-specifies JSON screens & visual tokens
                       │
                       ▼
                 [2. @architect] Updates `System_Architecture.md` & folders
                       │
                       ▼
                 [3. @engineer] Refactors frontend/backend code & updates DTOs
                       │
                       ▼
                 [4. @qa / @secdevops] Rewrites unit tests & audits new tech hooks
                       │
                       ▼
                 [5. @pentester] Adapts security attack scripts to new vectors
                       │
                       ▼
                 [6. @architect] Automatically rewrites the live Wiki in `docs/`

### How to apply a change safely:
Trigger /brainstorm to debate the new framework, database, or feature with @architect.

Give your formal approval ("I'm OK with this"), allowing the agent to save the new rules to the standards file.

Instantly type /startcycle.

The factory wakes up, reads the fresh delta from the specifications, and updates the code, test suites, security gates, and documentation simultaneously without code drift.
