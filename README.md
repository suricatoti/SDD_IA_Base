# 🤖 AI-Driven Software Factory (Spec-Driven Multi-Agent Architecture)

Welcome to the **AI-Driven Software Factory**. This repository is an autonomous, multi-agent development ecosystem designed to plan, architect, develop, secure, test, and document software applications dynamically.

Powered by **Spec-Driven Development (OpenSpec methodology)**, this framework eliminates AI hallucinations, code regression, and scope creep. Instead of writing code manually line-by-line, you will act as the **Product Owner / Tech Lead**, interacting with a team of specialized AI personas (Agents) through predefined workflows.

---

## 🏗️ Directory Architecture

The workspace is strictly organized to separate AI logic, specifications, and the actual application code.

```text
my-project/
├── .agents/                      # 🧠 The "Brain" of the Factory (Skills & Workflows)
│   ├── agents.md                 # Defines the AI personas and their models.
│   ├── project_standards.md      # The "Constitution" (Immutable tech stack & security rules).
│   ├── skills/                   # Prompt instructions for each agent's specific job.
│   └── workflows/                # The operational pipelines (e.g., /startcycle, /brainstorm).
├── openspec/                     # 📝 Spec-Driven Development (SDD) Contracts
│   ├── specs/                    # The "Main Spec" (The absolute Source of Truth for the project).
│   ├── changes/                  # Active "Delta Specs" (Proposals and changes currently being worked on).
│   └── archive/                  # Historical audit trail of merged Delta Specs.
├── app_build/                    # 💻 The Actual Application Codebase (Monorepo)
│   ├── frontend/                 # e.g., React.js / Vite
│   └── backend/                  # e.g., Node.js / Express
└── docs/                         # 📚 Living documentation generated by the Architect.
```


## 👥 Meet the Team (The Agents)
The system relies on a specialized team of AI personas, defined in `.agents/agents.md`. Each persona executes specific skills:

- **@pm (Product Manager)**: Interviews you, defines the MVP scope, and generates isolated Delta Specs (`openspec/changes/`) detailing exactly what needs to be `[ADDED]`, `[MODIFIED]`, or `[REMOVED]`.
- **@designer (UI/UX Designer)**: Reads the PM's specs, defines design tokens (colors, typography), and generates visual assets and UI JSON configurations.
- **@architect (Solutions Architect)**: Defines the system architecture, directory tree, database schema, and merges approved Delta Specs into the Main Spec.
- **@engineer (10x Full-Stack Developer)**: Writes the actual code and unit tests inside `app_build/`. **Strictly constrained** by the active Delta Spec to prevent altering out-of-scope business logic.
- **@secdevops (Security Auditor)**: Reviews the Engineer's code for vulnerabilities (e.g., IDOR, Mass Assignment, SQLi) and enforces security patches.
- **@qa (Quality Assurance)**: Validates if the code explicitly meets the Acceptance Criteria defined in the Delta Spec, tests edge cases, and verifies UI error messaging mappings.
- **@pentester (Offensive Security)**: Simulates black-box attacks on the compiled code to ensure absolute resilience.

## 🚀 How to Operate the Factory (Workflows)
You control the factory using trigger commands in your AI IDE chat.

### 1. The Planning Phase: `/brainstorm`
Before any code is written, you must define the technical landscape.
- **Command**: Type `/brainstorm I want to build a [feature]. What are the best architecture options?`
- **Action**: `@architect` acts as your Tech Partner, presenting multiple solutions, pros/cons, and evaluating trade-offs.
- **Outcome**: Once you agree on a technology, the Architect will automatically update the `.agents/project_standards.md` file.

### 2. The Execution Phase: `/startcycle` (OpenSpec Protocol)
Whether you are starting a project from scratch or adding a single button to a 5-year-old codebase, you use the same command.
- **Command**: Type `/startcycle`
- **Action**: This triggers the unified assembly line across 4 rigid phases:
  - **Propose**: `@pm` reads the Main Spec and creates a Delta Spec proposal. 🛑 **[HUMAN-IN-THE-LOOP]**: Execution PAUSES here for your manual approval of the markdown file.
  - **Apply**: `@engineer` writes code and tests *strictly adhering* to the approved Delta Spec.
  - **Validate**: `@qa` and `@secdevops` audit the code against the Delta Spec. If bugs are found, the `@engineer` is sent back to surgically refactor only the affected files (Circuit breaker active after 3 failed attempts).
  - **Archive**: `@architect` merges the approved Delta Spec into the main `openspec/specs/` directory, updates the `docs/`, and archives the cycle.

## 🔌 Using this Project as a Centralized Engine (Plugin Mode)

If you want to use this AI Factory architecture across multiple projects without duplicating the agent logic, you can configure it as a **Centralized AI Engine** via the `skills.json` feature.

This allows you to maintain and update your Factory's prompts in a single Git repository, while your actual application repositories remain clean.

### Setup Instructions
1. **Host the Engine**: Clone or push this repository (specifically the `.agents/` folder) to a central location on your machine or a remote Git repository. Let's assume you cloned it to `/path/to/openspec-factory-engine`.
2. **Target Project Setup**: In the actual project where you want to write code, create an `openspec/` folder and an `app_build/` folder.
3. **Link the Engine**: Inside your target project's root, create a `.agents/` folder containing a `skills.json` file and point it to your centralized engine:

```json
{
  "entries": [
    { "path": "/path/to/openspec-factory-engine/.agents/skills" }
  ],
  "inherits": [
    { "path": "/path/to/openspec-factory-engine/.agents/workflows" }
  ]
}
```

Now, your IDE will automatically inherit all personas, skills, and workflows (like `/startcycle`) from the central repository. 

**Why this is powerful:** Whenever you refine a prompt or add a new skill to your centralized engine, you simply pull the latest changes via Git. All your client projects will instantly inherit the upgraded AI intelligence!

## 📜 The Constitution: `project_standards.md`
The `.agents/project_standards.md` file contains the immutable technical rules for the project. It dictates the tech stack, security constraints, and prevention against common vulnerabilities. Never delete this file. If you want the AI to change its fundamental behavior, update this file via `/brainstorm`.

## 💡 Pro-Tip: Reverse-Engineering Legacy Code
You do not need to start from scratch. If you have an existing project with no documentation or tests:
1. Move your existing code into the `app_build/` folder.
2. Open the chat and type: `/startcycle @pm, read the existing code in app_build/ and reverse-engineer the Main Spec into openspec/specs/.`
3. The agents will document your current system. From then on, any new feature request will safely generate a Delta Spec, allowing the AI to evolve your legacy code without breaking it.

## 🔄 The Evolution Loop (Spec-Driven Cascade)
One of the most powerful features of this framework is its Spec-Driven propagation. When you request a change, the architecture handles it end-to-end without code drift:

```text
 [/startcycle] ➔ [1. PROPOSE] @pm generates `delta_xxx.md` in `openspec/changes/`
                       │
                       ▼
                 [2. APPLY] @engineer writes code locked to the Delta Spec
                       │
                       ▼
                 [3. VALIDATE] @qa / @secdevops audit code against the Delta Spec
                       │
                       ▼
                 [4. ARCHIVE] @architect merges the Delta into `openspec/specs/`
                       │
                       ▼
                 [5. DOCS] @architect automatically rewrites the live Wiki in `docs/`
```

**Zero Regression:** Because the `@engineer` is forbidden from guessing or refactoring code outside the active Delta Spec, your existing business logic remains perfectly safe during every cycle!
